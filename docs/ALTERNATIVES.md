# Альтернативные движки: что выбрать, если не llama.cpp/Rust

Мы остановились на **llama.cpp + Rust-обвязка**, потому что это единственный
вариант, который одновременно: работает на всех Android ABI, поддерживает GGUF
(тысячи готовых моделей), даёт KV-кэш по токенам и собирается в CI за минуты.
Но вот честное сравнение с альтернативами, если ваши приоритеты другие.

| Решение | Плюсы | Минусы | Когда брать |
|---|---|---|---|
| **llama.cpp / GGML (наш выбор)** | GGUF-экосистема, NEON/dotprod/i8mm-ядра, q4_k_m, KV-кэш с seq_rm, спекулятивное декодирование, Vulkan/OpenCL | C++ ядро, сборку надо готовить под ABI | локальный чат, 0.5–8B на телефоне |
| **MLC-LLM (TVM)** | GPU-ускорение (OpenCL/Vulkan/Adreno), компиляция под устройство | свои квантованные форматы (не GGUF), долгая компиляция, тяжёлый бинарник | когда нужна максимальная скорость на GPU |
| **MNN-LLM (Alibaba)** | очень хорошие arm82-ядра, поддержка Android/iOS, компактный | меньше моделей «из коробки», свой конвертер | китайские модели, промышленные приложения |
| **ONNX Runtime GenAI** | привычный ONNX, EP (NNAPI/QNN) | NNAPI для LLM слаб, квантование int4 через ORT даёт меньше tok/s, чем GGML | уже есть ONNX-пайплайн |
| **ExecuTorch (PyTorch)** | мобильный рантайм PyTorch, XNNPACK | LLM-поддержка молодая, int4-ядра хуже GGML | PyTorch-команда |
| **llama.rn (React Native)** | быстро поднять UI на JS | мост JSI добавляет задержки, тяжёлый бандл | прототип на RN |
| **Candle (HF, Rust)** | чистый Rust, удобно для эмбеддингов/маленьких моделей | на телефоне обычно медленнее GGML на LLM | кастомные архитектуры, wasm |
| **MediaPipe LLM Inference** | готовый API от Google, GPU-бэкенд | ограниченный набор моделей (.task/.bin), нет гибкого сэмплинга | быстрый прототип без своего движка |

## Почему Rust-обвязка вокруг llama.cpp, а не «переписать модель на Rust»

Генерация токенов ограничена **памятью**, а не языком: каждый токен = чтение
всех весов + один matvec. Поэтому скорость определяется:

1. форматом квантования и NEON-ядрами (это делает GGML, а не Rust);
2. тем, сколько раз вы прогоняете историю (KV-кэш — наш главный выигрыш);
3. числом потоков на big-ядрах и flash attention;
4. speculative decoding (единственный способ получить «в разы» на decode).

Rust даёт: детерминированную сборку, отсутствие GC/JNI-оверхеда в горячем
цикле, безопасные обёртки (не перепутать `llama_decode` и `llama_sampler_accept`)
и возможность гонять тот же движок на хосте в CI (`turbollm-bench`).

## Комбинированная схема, которую стоит попробовать следующей

* **arm64 + dotprod/i8mm**: собрать ggml с
  `GGML_CPU_ARM_ARCH=armv8.2-a+dotprod+i8mm` (флаг `GGML_CPU_ARM_ARCH` уже
  поддержан `llama-cpp-sys-2`, см. `scripts/build-apk.sh`) → +10–20% на decode;
* **draft-модель** Qwen2.5-0.5B к Qwen2.5-3B → 1.8–2.5x на decode;
* **GPU-путь** (Vulkan/OpenCL) для 3B+ моделей на Adreno 7xx/8xx → 1.5–4x,
  но следите за троттлингом и батареей;
* **MLC-LLM** как второй бэкенд для устройств, где GPU реально быстрее CPU.
