# Плагины: инструменты на HTTP

Плагин — это папка с манифестом `plugin.json`, которая добавляет агенту один или
несколько инструментов, реализованных как HTTP-запросы. Транспорт исполняется в
Kotlin (`PluginTools.java`), описание инструментов попадает в Rust через
`NativeBridge`, поэтому цикл агента ничего не знает о том, что инструмент
«внешний».

## 1. Поддерживаемые источники плагинов

| Вариант | Где лежит | Как подключить |
|---|---|---|
| Встроенный каталог | `assets/plugins/<name>/plugin.json` | «Инструменты → Установить плагин» |
| Импорт из файла | любой `*.json` через SAF | «Инструменты → Установить плагин → Из файла» |
| Ручной манифест | строка JSON, вставленная в диалог | «Инструменты → Свой MCP/плагин» |

Установленный плагин копируется во внутреннее хранилище приложения
(`filesDir/plugins/<name>/`) и перечитывается при старте.

## 2. Формат `plugin.json`

```json
{
  "name": "weather",
  "title": "Погода",
  "version": "1.0.0",
  "description": "Текущая погода по городу",
  "base_url": "https://api.example.com",
  "tools": [
    {
      "name": "weather_now",
      "description": "Текущая температура и состояние в городе",
      "method": "GET",
      "path": "/v1/now",
      "params": {
        "city": {"type": "string", "required": true, "in": "query", "description": "Название города"}
      },
      "headers": {"Accept": "application/json"},
      "timeout_ms": 10000
    }
  ]
}
```

### Поля верхнего уровня

| Поле | Обязательно | Смысл |
|---|---|---|
| `name` | да | идентификатор, `[a-z0-9_]`, используется как имя папки |
| `title` | нет | человекочитаемое имя для UI |
| `version` | нет | строка, показывается в списке |
| `description` | нет | уходит в системный промпт |
| `base_url` | нет | префикс, приклеивается к `path` (можно опустить и писать полный URL) |
| `tools` | да | массив инструментов, минимум один |

### Поля инструмента

| Поле | Обязательно | Смысл |
|---|---|---|
| `name` | да | имя, под которым модель вызывает инструмент |
| `description` | да | именно это читает модель, пишите «что делает и когда вызывать» |
| `method` | нет | `GET` (по умолчанию) / `POST` / `PUT` / `DELETE` |
| `path` | да | путь или полный URL |
| `params` | нет | схема аргументов; `in`: `query` (по умолчанию), `path`, `body` |
| `headers` | нет | статические заголовки запроса |
| `body_template` | нет | для `POST`: `{"q": "{{query}}"}` — подстановка аргументов |
| `timeout_ms` | нет | по умолчанию 10000 |
| `result_hint` | нет | подсказка модели, как читать ответ («массив объектов `items`») |

Подстановка аргументов — `{{name}}` в `path`, значениях `params` и `body_template`.
Значения URL-кодируются; в теле JSON — экранируются.

## 3. Как модель видит плагин

После установки и перезапуска чата описание попадает в общий список инструментов
рядом со встроенными:

```
Доступные инструменты:
- calc(expr: string) — вычисляет арифметическое выражение
- weather_now(city: string) — Текущая температура и состояние в городе
```

В режиме `auto` список вставляется в системный промпт; в режиме `re_act` — в
`react_tools_prompt()`. Дальше разницы нет: и `calc`, и `weather_now`
обрабатываются одним `AgentExec`-хуком, который в Kotlin решает, локальный это
инструмент или сетевой.

## 4. Безопасность и ограничения

* Сеть — только `https://`; `http://` разрешён лишь для `localhost`, чтобы можно
  было тестировать локальный MCP-сервер через `adb reverse`.
* Плагин не исполняет код: он умеет ровно HTTP-запрос. Это осознанно — так
  установка плагина не превращается в установку произвольного приложения.
* Тело ответа обрезается до 4 КБ перед возвратом в модель: длинные ответы
  съедают контекст и стоят токенов.
* Таймаут запроса — `timeout_ms`, сверху жёсткий потолок 30 с.
* Ошибки не «глотаются»: `Observation: ошибка инструмента weather_now: HTTP 401`
  уходит модели, и она обязана либо попробовать другой способ, либо дать финал.

## 5. Пример: курс валют без ключа API

```json
{
  "name": "fx",
  "title": "Курсы валют",
  "version": "1.0.0",
  "base_url": "https://api.frankfurter.app",
  "tools": [
    {
      "name": "fx_rate",
      "description": "Курс обмена между двумя валютами на сегодня",
      "method": "GET",
      "path": "/latest",
      "params": {
        "from": {"type": "string", "required": true, "in": "query", "description": "ISO-код, напр. USD"},
        "to": {"type": "string", "required": true, "in": "query", "description": "ISO-код, напр. TJS"}
      },
      "result_hint": "объект rates: {\"TJS\": 10.9}"
    }
  ]
}
```

Проверка вручную, до подключения к модели:

```bash
curl "https://api.frankfurter.app/latest?from=USD&to=TJS"
```

Такой же запрос выполнит приложение, поэтому если `curl` работает, инструмент
тоже заработает.

## 6. Отладка

1. «Инструменты» → список: у каждого плагина видно статус `ok` / текст ошибки
   манифеста.
2. Лог `adb logcat -s TurboLLM` — строки `plugin: <name> <method> <url>` и
   `plugin: <name> status=<code> bytes=<n>`.
3. Быстрая проверка одного инструмента без модели: в диалоге «Свой MCP/плагин»
   нажмите «Проверить» — приложение вызовет инструмент с тестовыми аргументами и
   покажет сырой ответ.

## 7. Частые ошибки

| Симптом | Причина |
|---|---|
| `плагин не установлен: нет поля tools` | манифест без массива `tools` |
| `неизвестный инструмент` | `name` инструмента не совпал с тем, что написала модель; добавьте псевдоним в `resolve_tool_name` |
| `HTTP 403` | нужен API-ключ: положите его в `headers` |
| Пустой ответ | API вернул 200 с пустым телом; используйте `result_hint`, чтобы модель не гадала |
| Долгий ответ | уменьшите `timeout_ms`, но не ниже 3000 |
